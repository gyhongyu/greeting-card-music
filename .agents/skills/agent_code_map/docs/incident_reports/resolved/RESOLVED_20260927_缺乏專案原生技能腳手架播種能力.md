## 二、 執行指令與現象
- **現象描述**：
  在 Cosmos 專案部署代碼地圖時，代理人將執行腳本手動放置於專案根目錄的 `scripts/code_map/`，並在 `AGENTS.md` 寫入命令。
  但當主人巡檢專案專屬技能目錄時，發現：
  ```bash
  dir E:\Projects\Cosmos\.agents\skills\
  # 輸出只有：project_structure_keeper
  # 找不到 agent_code_map！
  ```
- **核心痛點**：
  1. **缺乏專案原生技能腳手架 (Scaffolding)**：技能沒有提供一鍵將自身播種至專案 `.agents/skills/agent_code_map/` 的官方指令。
  2. **跨環境遷移失聯風險**：若專案 clone 到沒有安裝全域技能的新電腦上，因 `.agents/skills/` 內無該技能，新環境的 AI 代理人無法在 Skills 面板自動感知與主動喚醒該技能。
  3. **未被追蹤風險**：手動複製的 `scripts/` 目錄若未及時執行 `git add`，在新機器上會直接報錯 `No such file or directory`。

---

## 三、 根本原因分析 (Root Cause)
1. **技能定位封裝不完整**：
   `agent_code_map` 目前僅設計為「全域手動調用工具」，缺乏類似 `project_topology_architect` 的「專案播種 (scaffold/install)」能力。
2. **缺乏自包含規範 (Self-Containment Invariant)**：
   工業級 Agent 技能應支援雙模運作：
   - 模式 A（全域即插即用）：透過 `py skills\agent_code_map\...` 直接分析任何專案。
   - 模式 B（專案原生內聚）：提供 `--install / scaffold` 命令，自動在目標專案的 `.agents/skills/agent_code_map/` 建立標準 `SKILL.md` 與獨立運行腳本，隨專案 Git 倉庫版本化流轉。

3. **消除孤兒腳本**：
   不再將裸腳本散落於專案的 `scripts/code_map/`，統一收納於標準的 `.agents/skills/` 體系內。
